# Close crew's behaviour gaps and correct its documentation

Scope: `crew/crew.mjs`, `crew/crew.test.mjs`, and `crew/README.md`, with this plan under `crew/docs/`. Keep the existing structure. The baseline is crew 0.10.0; the source brief and the complete 28-item read-only report have been read.

## Outcomes

1. **Ignored files written after finish protect a waiting copy.** Replace directory-only ignored snapshots with individual file metadata. Bound inspection to 10,000 ignored entries and a fixed scan deadline; do not read file contents or follow directory symlinks. Record an explicit incomplete result on a limit, unreadable entry, or failed inspection. An incomplete baseline or later inspection keeps the copy waiting with a clear reason, even if the tree later shrinks. Older directory-only snapshots cannot establish that nothing changed and must also keep waiting. Only an explicit forced finish of the closed task can discard protected work, still subject to terminal safety. This trades automatic cleanup of very large trees for bounded work and honest protection rather than pretending directory timestamps cover file edits.

2. **A refused finish leaves the worker intact, and uncertainty after stopping remains recoverable.** Move every protective check possible with the worker alive ahead of stopping it, including uncommitted ship work, Git inspection failure, and `.artifacts/KEEP`. Preserve refusal messages and exit codes. Recheck protections after stopping to catch work written during the stop; explain in a comment why this check cannot happen earlier. Persist a postponed return rather than discard newly discovered work. If terminal removal or the second terminal listing cannot be confirmed, retain the copy and enough cleanup information for the next finish or start to retry safely. Output must distinguish an untouched refusal from a finished task whose copy still waits.

3. **Hand-over reconsiders the complete original candidate list.** Save the complete expanded, deduplicated configured chain in the person's order, including candidates passed over at launch and their reasons; retain quota-family information needed for later readings. Automatic hand-over and unnamed relaunch reread quota and installation eligibility for every candidate not already tried by that task, and still apply the existing floor grouping. Do not replace the saved chain with its currently usable remainder after hand-over. Preserve explicitly named relaunch semantics and compatibility with older task records. Status JSON continues showing remaining candidates and identifies passed-over candidates with the recorded reason and reading time, without implying status itself refreshed quota.

4. **Status JSON exposes the recorded delivery kind.** Add one `deliveryKind` field reporting `gate`, `workflow`, or `plain` for ship tasks from their recorded delivery choices; use `null` for tasks with no ship delivery. Keep existing status fields and delivery precedence unchanged.

5. **README and usage describe the resulting behaviour accurately.** Revisit all 28 report items against the current source, not stale line numbers. Cover profile selection, floors, quota reads, accounts, review/fix defaults, hand-over and wait distinctions, relaunch interruption, finish and deferred-return safeguards, backlog transitions, delivery selection and re-registration, land prerequisites, reviewer IDs, report truncation, best-effort workflow summaries, and status duration/protection reasons. Make small edits in existing passages rather than repeat explanations or restructure the README. Include items 25–28 under the brief's instruction to fix the entire report. List any disproved report item with source evidence instead of changing true text. Bump `VERSION` after implementing the fixes.

## Regression coverage

Write each behavioural regression before its fix and demonstrate its failure against the unchanged implementation:

- Overwrite an existing file inside an ignored folder after finish has postponed return, without changing the folder timestamp. Both a later start and a normal finish must preserve it; forced finish of the closed task may discard it only after holders leave. Cover the scan bound, incomplete baseline, and old coarse snapshots.
- Refuse dirty ship work, a keep marker, and failed work inspection while asserting that no worker stop, kill, removal, task closure, or copy return occurred. Simulate changes during stopping and a silent second Core listing; retries must recover without losing the copy or another terminal.
- Start with exhausted or rejected-login candidates ahead of the selected worker, recover them, and hand over automatically and through unnamed relaunch. Assert renewed readings, original preference order, no repeat of already tried candidates, preserved skip reasons, and visibility in status JSON. Keep missing-program, floor, shared-quota, account expansion, and named-choice behaviour intact.
- Assert the delivery-kind field for gated, workflow, plain, and non-ship tasks without changing selection rules.

After the approved implementation, `node crew/crew.test.mjs` must exit 0. The implementation report will state the ignored-tree strategy, regression results, any report corrections, and remaining limitations. This plan makes no runtime changes.
